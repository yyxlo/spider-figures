# 蜘蛛文獻圖片庫（NAS 資料夾版）

不需要伺服器，也不需要架網站。整個圖片庫就是一個資料夾，放在 NAS 的共用資料夾裡。能打開那個共用資料夾的人，雙擊 `index.html` 就能查詢。

- **查詢**：用科、屬、種學名或中文名搜尋，打字時會出現建議清單。可以用縮寫屬名（`A. ventri`），拼錯字時也會列出相近的名稱。
- **屬頁、物種頁**：依構造、性別篩選；文獻中使用舊名或舊組合的圖，會一併顯示在有效名底下。
- **並排比較**：選幾個物種並排，每張圖可以各自用滾輪縮放、拖曳移動。
- **新增圖片**：拖放圖片檔，或在新增頁面按 Ctrl+V 直接貼上從 PDF 截取的圖。縮圖會自動產生。
- **文獻**：複製引用格式、複製 BibTeX、連到 DOI。

需要 **Microsoft Edge 或 Google Chrome**。只瀏覽的話其他瀏覽器大多也能用，但新增與編輯一定要用這兩個瀏覽器。

## 安裝到 NAS

1. 取得這個資料夾，兩種來源擇一：
   - **全新開始**：從 GitHub 下載整個專案（Code → Download ZIP），解壓縮後取出 `nas-site` 資料夾。
   - **從 Docker 版搬過來**：見下方「從 Docker 版搬移資料」，匯出的資料夾已經包含所有圖片與資料。
2. 把整個資料夾複製到 NAS 的共用資料夾，例如 `\\NAS\Lab\蜘蛛文獻圖片庫`。資料夾名稱可以自己取。
3. 確認資料夾裡有 `index.html`、`app`、`data`、`images` 這幾項。

## 開啟

1. 用檔案總管進入 NAS 上的這個資料夾。
2. 在 `index.html` 上按右鍵 →「開啟方式」→ 選 **Microsoft Edge** 或 **Google Chrome**。
3. 建議把這個頁面加入瀏覽器的書籤，之後直接從書籤開啟。

## 新增與編輯

剛開啟時是**瀏覽模式**。要新增或編輯資料：

1. 按頁面上方黃色列的「**連接資料夾**」。
2. 在跳出的視窗中，選擇**放有 index.html 的那個資料夾本身**，按「選取資料夾」。
3. 瀏覽器會詢問是否允許編輯這個資料夾的檔案，選「**允許**」或「編輯檔案」。
4. 上方的列變成綠色「已連接資料夾」，就可以新增了。

之後同一台電腦再開啟時，瀏覽器通常會記得這個資料夾，可能只需要再按一次「連接資料夾」確認權限。

建議先到「**設定**」頁填入你的名字，新增的圖片會記錄是誰加的。

### 新增圖片的步驟

1. 按「新增圖片」，選擇物種（文獻圖上用的名稱，舊名也可以）。
2. 選擇既有的文獻，或勾選「這是新文獻」並填寫作者、年份、標題。
3. 拖入圖片，或在頁面上按 Ctrl+V 貼上截圖。每張圖可以分別填圖號、頁碼、構造、性別、視角。
4. 按「儲存到圖片庫」。

名錄裡找不到的物種名（例如舊名、同物異名），可以在「新增物種名」建立，並在「有效名」欄位指向現行有效名。已有的物種可以在物種頁按「編輯名稱資訊」，補上中文名或設定同物異名。

### 匯入名錄

「設定」→「匯入名錄」，選擇 CSV 或 TSV 檔，例如 World Spider Catalog 的匯出檔。網頁會依欄位名稱自動對應，對應不正確時可以手動調整，也可以只匯入指定的科。同名的種會更新，不會重複建立。

## 多人使用

- 其他人新增的圖，要**重新整理頁面（F5）**才會出現。
- 每張圖、每篇文獻都存成各自的小檔案，所以多人**同時新增**不會互相覆蓋。
- 兩個人**同時編輯同一張圖**的資訊時，會以最後儲存的為準。
- 如果有資料沒出現，到「設定」按「**重新掃描並重建索引**」。

## 備份

整個資料夾就是全部的資料，複製整個資料夾就是完整備份。建議使用 NAS 的快照或備份功能（QNAP 的 Hybrid Backup Sync 或快照）定期備份這個資料夾。

## 從 Docker 版搬移資料

在原本執行 Docker 版網站的電腦上，於專案資料夾執行（PowerShell）：

```powershell
git pull
docker compose up -d --build
docker compose exec web python manage.py export_static /app/export
docker compose cp web:/app/export .\蜘蛛文獻圖片庫
```

完成後，專案資料夾裡會多出 `蜘蛛文獻圖片庫` 資料夾，裡面已經包含名錄、文獻、所有圖片與網頁。把它整個複製到 NAS 即可。

要重新匯出時，先執行 `docker compose exec web rm -rf /app/export`，並刪除或改名舊的 `蜘蛛文獻圖片庫` 資料夾。

## 資料夾結構

```
index.html                  開啟這個檔案
app/                        網頁程式（不要修改）
data/library.json           圖片庫的識別檔
data/taxa.js                名錄（科、屬、種）
data/index.js               所有資料的索引，網頁開啟時讀取
data/records/figure/        每張圖一個 .json 檔
data/records/reference/     每篇文獻一個 .json 檔
data/records/species/       自行新增或修改的物種名
data/records/structure/     自行新增的構造類別
images/original/            原始圖檔
images/medium/              放大檢視用的中尺寸圖
images/thumb/               縮圖
tools/rebuild_index.py      用 Python 重建 data/index.js（網頁上的「重建索引」做的是同一件事）
```

請不要手動修改 `data` 裡的檔案。如果真的手動放入或刪除了記錄檔，到「設定」按「重新掃描並重建索引」，或執行 `python tools/rebuild_index.py`。

## 已知限制

- 網頁使用瀏覽器的「資料夾存取」功能寫入檔案，目前只有 Edge 和 Chrome 支援。
- 我是在 Linux 上的 Chromium 測試的。**從 Windows 選擇 NAS 網路資料夾**這一步沒有實際測過。如果「連接資料夾」時瀏覽器拒絕選擇網路資料夾，可以試試先把 NAS 共用資料夾「連線網路磁碟機」成一個磁碟代號（例如 `Z:`），再從 `Z:` 開啟 `index.html` 並選擇資料夾。這只是可能的解法，同樣未經測試。
- 沒有登入功能，誰能看由 NAS 共用資料夾的權限決定。
- 名錄很大時（例如整份 World Spider Catalog），第一次開啟可能需要幾秒鐘。
